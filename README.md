# speed-test-cli

Консольный скрипт на Python для замера **скорости скачивания** по заданному URL.
Делает N последовательных HTTP-запросов, дожидается полного тела ответа
на каждый, считает среднее время запроса, суммарный объём и итоговую
скорость скачивания.

## Требования

- **Python 3.9+** (используется только стандартная библиотека, внешних зависимостей нет).
- Никаких `pip install` не требуется.

Проверить версию:

```bash
python3 --version
```

> Для Python 3.8 добавьте в начало `speedtest.py` строку
> `from __future__ import annotations` — аннотация `tuple[int, float]`
> в рантайме там не вычисляется.

## Запуск

```bash
python3 speedtest.py <URL> [-n N]
```

- `<URL>` — адрес, к которому стучимся (например, тяжёлая картинка или файл для speed-теста).
- `-n`, `--requests N` — количество запросов, по умолчанию `10`.

### Быстрый пример

```bash
python3 speedtest.py https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg -n 3
```

Эта команда:

- скачает картинку `Fronalpstock_big.jpg` (~4.5 MB) с Wikimedia **3 раза**;
- для каждого запроса напечатает размер, время и скорость;
- в конце выведет среднее время, суммарный объём и среднюю скорость.

Ожидаемый вывод (числа у вас будут другие — зависят от канала):

```
URL:        https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
Запросов:   3
────────────────────────────────────────────────────────────
#01  размер:    4.52 MB  время:     1234 мс  скорость:   30.68 Мбит/с
#02  размер:    4.52 MB  время:      987 мс  скорость:   38.37 Мбит/с
#03  размер:    4.52 MB  время:     1102 мс  скорость:   34.36 Мбит/с
────────────────────────────────────────────────────────────
Успешных запросов:      3/3
Среднее время запроса:  1107.7 мс
Скачано всего:          13.56 MB (14219064 B)
Средняя скорость:       34.05 Мбит/с
```

## Справка `--help`

У скрипта есть встроенная справка — её печатает `argparse`:

```bash
python3 speedtest.py --help
```

Вывод:

```
usage: speedtest.py [-h] [-n REQUESTS] url

Замер скорости скачивания по URL (последовательные запросы).

positional arguments:
  url                   Адрес для скачивания (например, тяжелая картинка)

options:
  -h, --help            show this help message and exit
  -n REQUESTS, --requests REQUESTS
                        Количество запросов (по умолчанию 10)
```

Что означают поля:

- **`usage`** — краткая форма вызова: обязательный `url`, опциональный `-n`.
- **`positional arguments`** — аргументы, которые передаются без флагов
  (наш `url`). Он **обязателен**: без него скрипт выйдет с ошибкой
  `the following arguments are required: url` и кодом 2.
- **`options`** — флаги:
  - `-h`, `--help` — показать эту справку и выйти (код 0);
  - `-n N`, `--requests N` — сколько запросов сделать. Если не указать —
    берётся значение по умолчанию (`10`).

### Почему `-n` и `--requests` — одно и то же

Это **короткая** и **длинная** формы одного аргумента. Все три записи
эквивалентны:

```bash
python3 speedtest.py https://example.com/file.bin -n 5
python3 speedtest.py https://example.com/file.bin --requests 5
python3 speedtest.py https://example.com/file.bin --requests=5
```

Результат один: в коде будет `args.requests == 5`.

### Валидация аргументов

`argparse` сам проверяет:

- передан ли обязательный `url`;
- является ли значение `-n` целым числом (`type=int`) — иначе
  `error: argument -n/--requests: invalid int value: 'abc'`, код 2;
- не передан ли лишний неизвестный флаг — иначе `unrecognized arguments`,
  код 2.

Дополнительно скрипт проверяет бизнес-правило: `-n` должно быть **> 0**.
Иначе — `error: --requests должен быть > 0`, код 2.

Коды выхода:

| Ситуация | Код |
|---|---|
| Успех, хотя бы один запрос удался | `0` |
| Ошибка аргументов (`--help` не в счёт) | `2` |
| Ни один запрос не удался | `1` |

## Единицы измерения

- **Время** — миллисекунды (мс).
- **Объём** — байты; в выводе дополнительно в KB/MB/GB (1 KB = 1024 B, двоичные приставки).
- **Скорость** — **Мбит/с** (мегабиты в секунду, десятичные: 1 Мбит = 10⁶ бит):

  ```
  Мбит/с = (байты × 8) / (секунды) / 1_000_000
  ```

Десятичные мегабиты выбраны намеренно — так же измеряют провайдеры и
speedtest-сервисы, поэтому цифру можно напрямую сравнить с тарифом.

## Как это работает

1. Скрипт делает **N последовательных** запросов (не параллельно).
2. Для каждого запроса:
   - засекает время монотонными часами (`time.perf_counter`) **до** установки соединения;
   - открывает соединение с таймаутом 60 с;
   - читает тело **потоком** кусками по 64 KiB, считая байты, — чтобы не держать
     ответ целиком в памяти даже на больших файлах;
   - дожидается полного тела ответа (цикл до пустого чанка);
   - останавливает таймер **после** закрытия ответа.
3. Копит суммы по **успешным** запросам: `Σбайт`, `Σвремя`, `ok_count`.
4. Итоговая скорость считается как **взвешенная по объёму**:
   `Σбайт × 8 / Σвремя`, а не как среднее от скоростей отдельных запросов.
   Это устойчиво к разному размеру ответов и даёт честную среднюю
   пропускную способность за прогон.

## Ограничения на стороне сайтов (`429 Too Many Requests`)

Многие публичные сервисы **ограничивают частоту запросов** с одного IP.
Если сделать несколько запросов подряд к одному и тому же URL, сервер
может ответить:

```
#03  ошибка HTTP 429 Too many requests
```

Что это значит:

- `429 Too Many Requests` — сервер **узнал** клиента и **затормозил**:
  «слишком часто, отстань». Это **не баг скрипта**, а защита сервера.
- Часто вместе с кодом приходит заголовок `Retry-After: N` — «подожди N секунд».
- `#01` и `#02` при этом могут пройти успешно — лимит срабатывает не с первого
  запроса, а с третьего-пятого.

Скрипт **корректно** это обрабатывает: ловит `HTTPError`, печатает
сообщение в `stderr` и **продолжает** прогон. Итог считается по успешным
запросам. Если успешных нет — код выхода `1`.

### Что делать при 429

1. **Взять URL без лимитов.** .
2. **Уменьшить `-n`** — например, `-n 3` вместо `-n 10`.
3. **Добавить паузу между запросами.** В коде легко добавить флаг `--delay`:

   ```python
   p.add_argument("--delay", type=float, default=0.0,
                  help="Пауза между запросами, сек (по умолчанию 0)")
   ...
   if args.delay > 0:
       time.sleep(args.delay)
   ```

   Тогда `python3 speedtest.py <URL> -n 10 --delay 2` будет ждать 2 секунды
   между запросами, и лимит не сработает.
4. **Уважать `Retry-After`.** В `except HTTPError` можно прочитать
   `e.headers.get("Retry-After")` и сделать `time.sleep(int(retry_after))`
   перед следующим запросом.

## Где брать URL для теста

### Вариант для быстрой проверки скрипта

Картинка с Wikimedia — работает без лимитов на разумное число запросов,
удобно для «дымового» теста:

```bash
python3 speedtest.py https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg -n 3
```

~4.5 MB, три запроса — быстро, наглядно, безопасно.



### Локальный сервер (тест самого скрипта, не интернета)

```bash
dd if=/dev/urandom of=big.bin bs=1M count=100
python3 -m http.server 8000
# в другом терминале:
python3 speedtest.py http://127.0.0.1:8000/big.bin -n 10
```

Скорость будет «гигабитной» — ограничена только CPU и диском.
Полезно, чтобы убедиться, что скрипт вообще корректно считает.

## Известные ограничения

- **Один поток.** Запросы идут последовательно, в одном соединении на запрос.
  На «дальних» маршрутах с большим RTT одно TCP-соединение может не успеть
  разогнаться до полной полосы — поэтому цифра может быть ниже, чем у
  `speedtest.net`, который качает параллельно в несколько потоков. Это
  фундаментальное ограничение метода, а не баг.
- **Handshake на каждом запросе.** `urllib` не переиспользует соединения
  между вызовами — каждый запрос платит DNS + TCP + TLS. На файлах в десятки МБ
  это доли процента, но на маленьких файлах доминирует, и «скорость» получается
  заниженной. Для честного замера берите файл от 50–100 MB.
- **Ошибки не роняют прогон.** `try/except` стоит **внутри** цикла: упавший
  запрос логируется и пропускается, остальные выполняются. Итог считается по
  успешным; если успешных нет — код выхода `1`.
- Нет прогресс-бара, нет ретраев, нет параллельного режима — осознанные
  упрощения ради читаемости; добавляются отдельными флагами при необходимости.
